# 이 플러그인이 보내는 것

팀핑 플러그인이 내 컴퓨터에서 보내는 항목 전부예요. README에서 이 문서로 연결돼요.

← [README](https://github.com/serion-mark/teamping-plugin/blob/main/plugin/README.ko.md) · [English](https://github.com/serion-mark/teamping-plugin/blob/main/plugin/DATA.md)

## 경로와 도구 이름만 보내요

훅이 보내는 것은 **경로 · 도구 이름 · 시각 · 순서**이고, 파일 내용은 보내지 않습니다(토큰을 찾으려고 git 상태와
`.mcp.json` 은 내 컴퓨터 안에서 읽습니다). 훅은 **플러그인이 켜진 모든 저장소에서 돕니다 — 아직 팀핑 프로젝트에 연결하지 않은 저장소도 포함됩니다.**
아래 「저장소 주소」는 설정된 git `origin` 주소 그대로입니다 — 주소에 인증 정보가 박혀 있으면(`https://user:token@…` 처럼)
그것도 나가므로 `origin` 에 토큰을 넣지 마세요. `origin` 이 없는 git 저장소는 폴더 이름이 갑니다.
**git 이 없는 폴더는 직접 정한 폴더만 기록합니다** — AI 에게 「이 폴더도 기록해 줘」라고 하면 됩니다(이 플러그인의
`node scripts/teamping-folders.mjs add [폴더]` 를 실행 · 빼기 `remove` · 목록 `list` · 직접 쳐도 됩니다). 정한 폴더에서는 저장소 주소 대신
`dir:` 와 임의 id 가 가고(폴더 이름이 아닙니다) 경로는 그 폴더 기준이며, 도구 뒤 훅은 셸 명령이 그 폴더에서 바꾼 파일도 수정 시각으로 찾아 싣습니다.
정하지 않은 git 없는 폴더는 폴더·파일 정보를 보내지 않습니다(세션 시작 브리핑은 저장소 없이 묻고, 세션 종료는 이 창의 잠금을 풉니다).
「창 id」는 이 기계에서 Claude 창마다 만드는 해시입니다(기기·사용자 이름이 들어 있지 않습니다).

| 훅 | 언제 | 보내는 것 |
|---|---|---|
| `SessionStart` | 창을 열 때 | 세션 id · 창 id · 저장소 주소 · 에이전트 이름 (설치 시 채널을 지정했으면 그 채널) · 플러그인 판 번호 · 시간대 오프셋 · 표시 언어 · 이 레포의 커밋 전 확인 상태 한 단어(`off`·`on`·`declined`·`custom`) |
| `PreToolUse` | 편집 직전 (`Edit`·`Write`·`MultiEdit`·`NotebookEdit` · `Bash` 의 쓰기 대상) | 세션 id · 창 id · 에이전트 이름 · 저장소 주소 · 파일 경로(상대경로) · 도구 이름 · 표시 언어 |
| `PostToolUse` | 모든 도구가 끝난 뒤 | 세션 id · 에이전트 이름 · 저장소 주소 · 도구 이름 · 바뀐 파일 목록(상대경로 · 최대 50개) · 도구 결과의 바이트 길이 · **이 레포의 새 커밋 sha(최대 20개 — sha 뿐, 메시지·diff 없음)** · 보조 에이전트가 부른 경우 그 id · AI 가 방금 작업 카드를 집었으면 그 카드 id · 이 창이 AI 에게 이미 보여 준 팀핑 연락의 id(다시 안 받게) · AI 가 방금 팀핑에 글을 올렸으면 그 글 id |
| `SessionEnd` | 창을 닫을 때 | 세션 id · 창 id · 보낸 시각 |
| `UserPromptSubmit` | 내가 말을 보낼 때 | 세션 id · 저장소 주소 · 이미 보여 준 연락의 id · 창에 제목을 붙였으면 그 제목(팀에게 창 이름으로 · 내 팀핑 알림에 보임) — 내가 쓴 말은 보내지 않습니다 |
| `Stop` | 응답이 끝날 때 | 창이 쉬는 동안 팀핑 연락을 기다립니다: 세션 id · 저장소 주소 · 이미 보여 준 연락의 id (그 밖엔 없음 — 로컬 문구만) |

이 플러그인의 스크립트 둘은 **훅이 아닙니다** — 직접 배선해야 돌아갑니다.

| 스크립트 | 언제 | 보내는 것 |
|---|---|---|
| `precommit-lock.sh` | 설치한 뒤, git 커밋 직전에 | 저장소 주소 · 스테이지에 올린 파일 경로 목록 |
| `notify-deploy.sh` | 직접 배포 절차에서 부를 때 | 저장소 주소 · 배포한 커밋 sha · 그 구간 커밋들의 sha(최대 200개) — **sha 뿐이고 커밋 메시지나 diff 는 안 보냅니다** |

**이 창에 온 팀핑 연락.** 누가 이 창이 쓴 글에 답장하거나, 이 창이 집은 카드에 의견을 남기거나 확인하거나, 다른 AI 가 이 창을 골라 글을 보내면 팀핑이 이 창 몫으로 한 줄을 둡니다(누가 · 무엇을 · id · 읽는 도구 — 본문은 넣지 않습니다). 훅이 그 줄을 도구가 끝난 뒤 · 내가 말을 보낼 때 · 응답이 끝날 때 한 번 AI 에게 넣고, 창이 쉬는 동안엔 뒤에서 도는 `Stop` 훅이 기다리다 창을 깨웁니다(내가 입력하지 않는 동안 한 시간에 최대 6번 · 입력하면 다시 셈 · 그래도 한 시간에 20번을 넘지 않음 · 50분 기다리면 다음 응답 끝까지 쉼). AI 는 그 줄을 받으면 먼저 사용자에게 알리고 이어서 할지 묻도록 안내받습니다. 보여 줄 줄과 이미 보여 준 id 는 `~/.config/teamping/inbox/` 에 둡니다(폴더 0700 · 파일 0600 · 창마다 따로 · 8일 지나면 지움). 보조 에이전트 안에서는 넣지 않습니다.

**셋업 이어하기.** 셋업 키트로 연결하다 앱을 다시 켜야 할 때, AI 가 이 컴퓨터의 `~/.config/teamping/setup/<레포별 열쇠>/` 에 키트 사본과 이어 할 단계·사본 해시를 남깁니다(레포는 건드리지 않음 · 비밀값 없음). 다시 연 세션에서 `SessionStart` 가 그걸 읽어, 사본 해시와 레포 경로가 맞을 때만 AI 에게 그 단계부터 이어서 하라고 알립니다 — 아무것도 보내지 않습니다. 7일이 넘은 메모는 따르지 않고 지운 뒤 한 번만 알립니다. 셋업이 끝나면 AI 가 지웁니다.

**Grok Build(xAI · 0.2.36).** Grok Build 는 Claude Code 플러그인을 그대로 읽어 이 훅들을 Grok 안에서도 돌립니다. Grok 만 쓰면 `grok plugin marketplace add serion-mark/teamping-plugin` 과 `grok plugin install teamping@teamping-plugin --trust` 로 설치합니다. Grok 안에서 도는 것을 알아보면 Grok 의 도구 이름(`write` · `search_replace` · `run_terminal_command`)을 알아보고, 기록 이름을 Claude Code 가 아니라 Grok 으로 보내며, 열쇠는 `~/.grok/config.toml`(`$GROK_HOME` 이 있으면 그 안)의 `[mcp_servers.teamping]` 에서 먼저 찾습니다. 그 항목(또는 파일)이 있는데 못 읽으면 거기서 멈춥니다. 항목이 없으면 내 Claude Code 설정(`~/.claude.json`)의 이 폴더 항목이나 로그인 연결의 레포별 자동 잠금 열쇠만 씁니다 — 그 파일 최상위의 복사 열쇠는 다른 회사 것일 수 있어 쓰지 않습니다. 레포 안 `.mcp.json` 은 Grok 에서 쓰지 않습니다. Grok 의 MCP 도구 이름(`teamping__…`)도 알아봅니다. 받은편지함·세션 안내 훅은 Grok 에서 아직 건너뜁니다.

**자동 잠금 열쇠(로그인 연결 · 0.2.35).** Claude Code 를 로그인(`claude mcp add` + 브라우저)으로 팀핑에 붙이면 연결 열쇠는 Claude Code 자신의 보관소에 있어 훅이 읽을 수 없습니다. 동의하면 플러그인이 `127.0.0.1` 에 한 번용 수신기를 열고 브라우저로 팀핑 동의 화면을 연 뒤(프로젝트를 고르고 허용), 팀핑 도구는 못 쓰고 잠금·기록 훅만 여는 열쇠를 `~/.config/teamping/hookkey/<레포별 열쇠>` 에 저장합니다(폴더 0700 · 파일 0600 · 레포마다 하나 · 같은 레포의 작업 폴더는 함께 씀). 보내는 것: 포트 · 운영체제 종류(맥·리눅스) · 이 컴퓨터와 레포를 한 방향 변환한 값(경로·레포 이름 없음) · 사람·회사 id. 마이페이지 「연결 열쇠」에서 끊을 수 있고, 끊으면 다시 켤 때까지 팀핑이 훅의 요청을 거절합니다(파일은 그때까지 남습니다). 로그인 연결로 보는 것은 내 Claude Code 설정(`~/.claude.json`)의 항목뿐입니다 — 레포 `.mcp.json` 의 열쇠 없는 `teamping` 항목은 예전처럼 건너뜁니다.

**커밋 전 확인은 레포마다 켜는 선택입니다.** 꺼져 있으면 세션 시작 브리핑이 하루 한 번 켤지 묻고, 켜면 플러그인의 설치 스크립트가 이 기계의 `.git/hooks/pre-commit` 첫 줄 아래에 표식 달린 블록 하나를 넣습니다(저장소에 커밋되지 않음 · 기존 훅 내용은 그대로). 켠 뒤엔 `SessionStart` 가 그 블록 안의 경로를 지금 플러그인 판으로 맞춥니다(새 판을 받으면 옛 판 폴더가 지워지기 때문) — 블록 밖은 건드리지 않습니다. `core.hooksPath`(husky 등)를 쓰는 레포 · 심볼릭 링크 훅 · sh 계열이 아닌 훅은 건드리지 않습니다(설치 스크립트가 넣을 줄만 알려 줍니다). 그만 묻게 하려면 `git config teamping.precommit off`.

나가지 않는 것: 파일 내용 · 소스코드 · 명령어 원문 · 도구 출력 본문 · 대화 · 프롬프트 · 환경변수 · API 키 ·
절대경로 · 프로젝트 밖 파일(잠금 기준) · 커밋 메시지.
위에 적은 것이 전부이고, 전부 이 플러그인에 실린 훅 스크립트(`plugin/scripts/`)가 만듭니다 — 직접 열어 볼 수 있어요.

**토큰이 어디서 오고 요청이 어디로 가나.** 훅은 이미 `.mcp.json` 에 있는 팀핑 토큰을 다시 씁니다
(프로젝트 → 폴더 → 사용자 순서). 새로 설정할 것은 없습니다. 찾은 결과는 `~/.cache/teamping/tok/` 에
`0600` 권한으로 캐시합니다. 훅은 **그 `teamping` 항목의 서버 주소**로 보냅니다 — 그래서 저장소 안의 `.mcp.json` 이
훅을 다른 서버로 보낼 수 있습니다. 믿을 수 있는 저장소만 열고, 프로젝트 `.mcp.json` 의 `teamping` 주소를 확인하세요.
`notify-deploy.sh` 는 추가로 `TEAMPING_BASE`·`TEAMPING_TOKEN` 환경변수나 `~/.teamping-token` 파일도 받습니다 —
자격증명 설정처럼 다루십시오.

훅이 실제로 무엇을 받는지 값 없이 볼 수 있습니다. `TEAMPING_HOOK_DEBUG=/경로/파일.jsonl` 을 주면
훅이 받은 것의 **구조**(키 · 타입 · 길이)만 그 파일에 남깁니다.
